# AGENTS.md

ACS is a 2-D geometric constraint solver: a Rust crate (`src/`) with WASM bindings, plus a React demo app (`wasm-demo/`).

## Commands

- Build: `cargo build`
- Lint (CI-enforced): `cargo clippy --all-targets --all-features`
- Test all: `cargo test`
- Single test file: `cargo test --test horizontal_test` (one integration test file per constraint in `tests/`)
- Pre-solver benchmark (a test, not `cargo bench`): `cargo test presolver_bench -- --nocapture`
- WASM build: `wasm-pack build --target web --out-dir pkg`
- C ABI tests (incl. a C smoke test that builds `libacs.a` and compiles `tests/c/smoke_test.c` with `cc`): `cargo test --features c-abi`
- Release: push a tag `vX.Y.Z` matching `Cargo.toml`'s version; `.github/workflows/release.yml` runs parallel jobs (clippy + tests + `cargo publish --dry-run` on Linux; one macOS job per Apple platform running `scripts/release.sh <platform>`; the WASM package on Linux via `scripts/release.sh wasm`), then one job publishes a GitHub Release and publishes the crate to crates.io (`CARGO_REGISTRY_TOKEN` secret; a manual run only builds). The crate is `acs-solver` on crates.io (`acs` is taken) but the library is `acs` (`[lib] name`), so `use acs::…`, `libacs.a` and wasm-pack's `acs.js`/`acs_bg.wasm` keep their names; the npm package is `acs-solver`, and `scripts/release.sh` renames its tarball to `acs-<version>.tgz`. Cargo.toml's `include` keeps the crate to the library (no demo, tests, scripts or docs). Release artifacts (static library + npm package): `scripts/release.sh [piece...]` -> `dist/` (no argument: everything, the Apple targets in one cargo invocation and wasm-pack alongside in `target/wasm-release`) (macOS arm64, iOS arm64, iOS Simulator `acs-<version>-<platform>.tar.gz` + the npm tarball `acs-<version>.tgz`; the version is the crate's)
- Demo: `npm run dev` / `npm run build` / `npm run test` (vitest) in `wasm-demo/`

CI (`.github/workflows/rust.yml`) runs clippy -> build -> test -> wasm-pack build. Keep clippy clean.

## Architecture

- `src/constraints/` — one file per constraint implementing the `Constraint` trait from `constraints/base.rs` as a **kernel**: `vars()` names the variables it reads by role (`Var::X/Y/Radius/StartAngle/EndAngle`, `xy(id)`; a Var is a number the solver moves, never a sketch Parameter (`param`)), and `eval(x, r, j)` computes residuals and partials over those *local* values. A constraint may also declare **Guides** (`guides()`, default none): inputs `eval` reads after the `vars()` that the constraint copies across (mirror axis, array center/direction). `j` has a column per `reads(c)` (= vars then guides) with exact partials for all of them, and every solve, drags included, moves Guides like any variable. The trait's provided `residual`/`jacobian` (and `eval_into`) do the ID lookup and accumulate (`+=`) into the global Jacobian, so shared points (two lines meeting at a corner) are handled once, for every constraint. Never write global Jacobian columns in a constraint.
- `src/solver.rs` — `ConstraintSolver`, the public Rust API (string-ID based): holds geometry + constraints, delegates `solve` and `fully_constrained_entity_ids` to `SketchSystem`.
- `src/sketch_system.rs` — built once per solve/analysis: the variable vector, and per Component its constraints (the sketch's plus each arc's implicit rules) and *free* columns (fixed variables are never columns). Skips already-solved Components (the pre-solver), solves the rest one by one on Component-sized systems, writes back to geometry, and runs the degrees-of-freedom analysis and Conflicting/Redundant diagnosis on the same structure (both over non-temporary constraints only). Temporary constraints are soft goals, solved by `solve_with_goals` (method in its doc comment: Dog-Leg restores the real constraints, then a feasible trust-region SQP: steps in the null space of the real Jacobian from a model with the Lagrangian's Hessian (central differences of the analytical Jacobians, `ReducedModel`), each re-projected with Dog-Leg. The second-order model is what gets a drag past a *fold*, where a real constraint changes only quadratically in the direction the goal needs, e.g. a fixed-length edge that starts exactly horizontal; a first-order method stalls there with the goal unmet — `tests/planegcs_dialect_test.rs` `a_drag_at_a_fold_reaches_the_cursor`).
- `src/dogleg_solver.rs` — Dog-Leg trust-region numeric core: `solve_dl(x, eval)` over a plain vector and an `eval(x) -> (residuals, Jacobian)` callback; knows nothing about sketches. Owns `TOLF` (1e-10).
- `src/component_graph.rs` — `find_components`: union-find over the entities each constraint reads (`reads()`: Guides included, so a copy is solved with whatever moves its Guide). Guides are Component columns like any variable (a free axis keeps its own degrees of freedom in `dof`, and its copies aren't `fullyConstrained`).
- `src/constraint_catalog.rs` — the two constraint vocabularies (`Vocabulary::Native` / `PlaneGcs`), one table each: `constraint_catalog/native.rs` (ACS's own: one type per relationship, role-named fields, several rows per type = variants, chosen by the kinds of the referenced entities and the `extension` and `internal` flags (`internal: true`: the inside variants of `distance` point–circle and circle–circle; `ConstraintSpec::internal`, catalog `internal: true`); `a`/`b` of `distance`/`tangent`/`concentric`/`equal` in either order; unsupported combinations rejected naming the kinds) and `constraint_catalog/planegcs.rs` (the GCS types, one row each, mapped straight onto `ConstraintType`s, not onto native JSON). A row (`ConstraintSpec`) is a JSON type, fields by kind (point/line/circle/arc/ellipse/scalar/value/axis), an `ExtensionFlag`, a `deprecated` flag and a builder to `ConstraintType`. A field name `name[i]` is element `i` of an array field (`field_path`/`field_value`; the catalog emits `{name, index, kind}`); native `midpoint`'s `entities` is the only one. Shared resolution: lines to endpoints, circles/arcs to centers, ellipses to center + focus (`EllipseRef`), `axis` to `EllipseAxis` (`"major"`/`"minor"`), Parameter ids to constants (`References::scalar`) and property references (native `{entity, property}`, dialect `{o_id, prop}`) to `Operand`s (`References::operand`, `property_operand`). `Vocabulary::catalog_json` serves `acsConstraintCatalog` / `acsPlaneGcsConstraintCatalog`.
- `src/sketch_solve.rs` — JSON sketch API: `solve_sketch_json_in(Vocabulary, request)` parses primitives, builds constraints through the vocabulary's catalog, solves, builds the response. `solve_sketch_json` = native, `solve_planegcs_sketch_json` = dialect; the envelope, geometry and Parameters are shared.
- `src/bindings/` — wasm-bindgen wrappers: `acsSolveSketch` + `acsConstraintCatalog` (native), `acsSolveSketchPlaneGcs` + `acsPlaneGcsConstraintCatalog` (dialect).
- `src/c_abi.rs` — behind the `c-abi` feature: `P3DSketch_Solve` / `P3DSketch_Free` (the sketch solver C ABI, header `include/p3d_sketch_solver.h`) over `solve_sketch_json_in` in the vocabulary its `vocabulary` argument names (`P3DSketchVocabulary`: `P3D_SKETCH_VOCABULARY_PLANEGCS` = 0, `P3D_SKETCH_VOCABULARY_NATIVE` = 1; any other value -> `invalid`; `Ok` -> 0, `Err` -> 1; null/non-UTF-8 request and panics -> `invalid` response). The crate also builds a `staticlib`; the release script renames it `libp3d_sketch_solver.a` in the layout a consumer's setup script extracts. WASM doesn't use the feature.
- `pkg/` — **generated** by wasm-pack and gitignored; `wasm-demo` depends on it via `"acs": "file:../pkg"`. Run `wasm-pack build --target web --out-dir pkg` before `npm install`/`npm run dev` in the demo, and re-run it after any Rust change for the demo to pick it up.

## Adding a constraint

Touch all of these (grep an existing constraint like `Concentric` as a template). Tests fail until steps 1–5 agree:
1. `src/constraints/<name>.rs` (`vars` + `eval`, plus `guides` for inputs a drag must never move through it (with exact partials like the rest); reuse `segment.rs` for anything measured against a Line) + re-export in `src/constraints/mod.rs`
2. `ConstraintType` enum + `create_constraint` match in `src/constraints/base.rs`
3. Rows in the catalogs: a native row (or a new variant of an existing native type) in `src/constraint_catalog/native.rs`, and a row in `src/constraint_catalog/planegcs.rs` if the dialect has a GCS type for it. These drive the JSON APIs, both catalog exports, `tests/catalog_rows_test.rs` (every row of both vocabularies solves through every entry point) and the finite-difference test, which builds each internal `ConstraintType` once from the first row (native first) that reaches it. Also add the variant to `variant_name`/`ALL_VARIANTS` in `tests/jacobian_fd_test.rs` (the exhaustive match won't compile otherwise).
4. Demo: an entry per native row (except `deprecated` ones) in `CONSTRAINT_DEFS` in `wasm-demo/src/core/constraints/registry.ts` (unique `key`, native `type`, `extension` if the row has the flag, `internal: true` on inside rows); `registry.test.ts` checks the set field-for-field against `acsConstraintCatalog`.
5. `tests/<name>_test.rs`; shared-point cases in `shared_point_constraints()` if two arguments can be the same point
6. Docs: constraint tables in `README.md`, `USAGE.md`; residual/Jacobian math in `SPEC.md`

## Conventions

- Rust edition 2024. Jacobians are analytical (derived in `SPEC.md`), not numeric — new constraints must include exact partial derivatives. Verify them by adding the constraint to `tests/jacobian_fd_test.rs`. Wrong product-rule terms have shipped before, including in `SPEC.md` tables, so derive from the code or check numerically rather than copying the spec.
- Geometry entities are referenced by string IDs; constraints on lines/circles usually take the underlying point IDs, not the line ID (see `ConstraintType` variant comments).
- The JSON API contract (input/output shapes, constraint type strings) is documented in `USAGE.md`; keep it in sync with `sketch_solve.rs`. Docs have drifted from code before — trust the code.

## Solver / API facts (verified in code)

- Convergence and pre-solver skip both use L-inf residual < `1e-10` (`TOLF` in `dogleg_solver.rs`). Per-component stats: iterations summed, errors maxed.
- A Line is a **segment**, never infinite (unlike PlaneGCS). `PointOnLine`, `DistancePointLine`, `TangentLineCircle` (tangency point on the segment), and `MidpointOfLineOnLine` all measure against the segment via shared helpers in `src/constraints/segment.rs`. Parallel/Perpendicular/Angle use only direction. Only the Extension variants (`PointOnExtension`, `DistancePointExtension`, `TangentExtensionCircle`, `MidpointOfLineOnExtension`; native `extension: true`, dialect `*_extension_*`), `SignedDistancePointExtension` (`offset`) and `MirrorPointExtension` (`mirror`; dialect `mirror_point_ppl` and `p2p_symmetric_ppl`) measure against the infinite line, via `line_signed_distance`; they exist for sketches migrated from PlaneGCS.
- An Arc references center, start and end Points (`c_id`, `start_id`, `end_id`, all required) and owns `radius`, `start_angle`, `end_angle` as Vars; it sweeps counter-clockwise from start to end (sweep `(end − start) mod 2π`, 0 = full turn). Its endpoints always lie on it: `SketchSystem` adds an implicit `ArcRulesConstraint` per arc (`implicit_arc_rules`, indices past the sketch's constraints), which joins the arc's Component, holds exactly under soft goals, and counts in `dof`, `fullyConstrained` and diagnosis (a contradiction with it reports the *other* constraints Conflicting; in the Redundant walk it's never dropped), but is never itself reported. So a free arc has 5 DOF. An explicit `ArcRules` over an arc's own center/start/end (what `arc_rules` builds) gets `Role::Implied` in `ConstraintSolver::push_constraint`: in no Component, never reported, no effect on `dof`. One over other Points stays a real constraint. Like a Line is its segment, an Arc is its span: `PointOnArc` and `TangentLineArc` (`point_on_arc`, `tangent_la`) keep the point/tangency point within the span via `span_overshoot` in `src/constraints/arc_span.rs`; `tangent_la` also keeps it on the segment, like `tangent_lc`. `point_on_circle` with an arc id still means the full circle.
- An Ellipse (`{c_id, focus1_id, radmin}`) references center and focus Points and owns `radmin` as `Var::MinorRadius`; major radius `√(radmin² + |f − c|²)`, so a free ellipse has 5 DOF. Its kernels (`point_on_ellipse.rs`, `tangent_line_ellipse.rs`, `ellipse_axis_point.rs`, `ellipse_diameter.rs`) compute residuals in forward mode over `constraints/ellipse.rs` (`D<N>`/`V2<N>`/`EllipseFrame`: exact partials by the chain rule, like GCS's `DeriVector2`); reuse it for new ellipse constraints. Native `on` (curve ellipse), `tangent` line–ellipse (tangency point on the segment, like `tangent_lc`; no Extension variant) and `ellipse_axis` (`ellipse`, `point`, `which`: one point at *either* end of the axis; or `ellipse`, `a`, `b`, `which`: `EllipseDiameter`, the two opposite ends); dialect `point_on_ellipse`, `tangent_le`, `internal_alignment_ellipse_major_diameter`/`_minor_diameter` (`EllipseDiameter`: the pair symmetric about the center along the axis, ends unordered). `fullyConstrained` lists an ellipse when its `radmin`, center and focus are all locked. Other GCS ellipse types (focus alignments, `arc_of_ellipse`) are unknown types.
- `isReference: true` on any geometry primitive implies `fixed` (`sketch_solve::fixed`): Reference Geometry's own values (point coordinates, circle radius, arc radius and angles, ellipse `radmin`) never move. Like `fixed`, it doesn't reach referenced Points.
- `ConstraintSolver::add_constraint` rejects constraints whose entities are missing or the wrong kind (`'id' is not a point`); the JSON API rejects the request with `constraint <id>: <msg>` and `constraintId`.
- Line–arc tangency where a line endpoint *is* an arc endpoint (same id, e.g. a slot) is built as `TangentAtPoint` (line ⟂ radius at the shared point) by `Args::tangent_line_arc` in both vocabularies: the distance form (`TangentLineArc`) is degenerate there (zero Jacobian row at tangency → spurious Redundant, `dof` too high). Any constraint whose residual can only touch zero from one side at the solution has the same problem; prefer a form that changes linearly.
- `SolverResult::Converged` means L-inf residual < `1e-10`; a stall in a local minimum (vanished gradient, collapsed trust region) is `MaxIterationsReached`.
- `tests/jacobian_fd_test.rs` checks every constraint's analytical Jacobian against finite differences, including shared-point variants. It differences every variable a constraint reads, Guides included, and requires columns of variables it doesn't read to be zero. Add new constraints to `all_constraints()` (and `shared_point_constraints()` if two arguments can be the same point). Prefer unsquared residuals when the target can be 0 (a squared residual has a zero Jacobian row at the solution, which breaks convergence and DOF analysis).
- Two vocabularies, one contract. Native (`solve_sketch_json`, `acsSolveSketch`): types `coincident`, `horizontal`/`vertical`, `parallel`, `perpendicular`, `angle`, `direction`, `distance`, `offset`, `on`, `midpoint` (`entities: [point|line, line]`; `{point, line}` and `midpoint_on` are deprecated rows, `.deprecated()`, removed in 0.1.7), `tangent`, `concentric`, `equal`, `radius`, `diameter`, `length`, `difference`, `x`/`y`, `mirror`, `rotation`, `translation`, `ellipse_axis`, table in `USAGE.md` (`angle` with an `arc` is its sweep, only `0 < value < 2π`, residual unwrapped near the target; `distance` also takes point–circle, line–circle, circle–circle as signed gaps and line–line, SPEC §22). PlaneGCS dialect (`solve_planegcs_sketch_json`, `acsSolveSketchPlaneGcs`, `P3DSketch_Solve`): the GCS types below, unchanged; `p2p_symmetric_ppp` -> `Midpoint`, `p2p_symmetric_ppl` -> `MirrorPointExtension` (there is no `symmetric`). Neither accepts the other's type names. The dialect tests are `tests/planegcs_dialect_test.rs` (also through `acsSolveSketchPlaneGcs`), the native ones `tests/native_vocabulary_test.rs`.
- The JSON contract is the `P3DSketch_Solve` contract: request `{version: 1, primitives, maxIterations?}`; response `{version: 1, status: converged|failed, primitives (same order), conflicting, redundant, dof}` plus ACS extensions `fullyConstrained` and `stats`. It returns `Err` with `{version: 1, status: "invalid", error, constraintId?}` for anything it can't read (wrong version or `maxIterations`, duplicate id, unknown type, missing field, missing/wrong-kind entity); `constraintId` names the offending constraint when there is one. `param` primitives are Parameters: constants (`value`) echoed back unchanged. Any `scalar` field takes a number, a Parameter id or a numeric string (unknown id -> rejected); `value` fields (only `difference`/`equal`) also take a property reference (native `{entity, property}`, dialect `{o_id, prop}`) with props point `x`/`y`, circle/arc `radius`, ellipse `radmin`, which become `Operand::X/Y/Radius/MinorRadius` vars the solver moves. `p2l_signed_distance` (`SignedDistancePointExtension`) is an Extension constraint signed by `side` (<0 -> -1, else +1; +1 = left of p1->p2). Array/mirror types match PlaneGCS's fork: `p2p_angle` (`PointPointAngle`, residual `atan2`, no θ+π root), `mirror_point_ppl` (`MirrorPointExtension`, mirrors across the axis Line's Extension), `circular_instance` (rotate `p0` about `center_id` by `angle`), `linear_instance` (move `p0` by `base_distance·N` along unit `dirP1->dirP2`); `angle`/`base_distance`/`N` are scalars. The axis/center/direction points are Guides, ordinary unknowns in every solve (unlike the fork, which never moves them through these constraints): moving them (by a drag or other constraints) moves the copy; real constraints move a free Guide as they need (Horizontal on a side of a patterned polygon turns it about a center that moves with it; a mirror whose source and image are both fixed turns a free axis onto their perpendicular bisector); and dragging the source or a copy may move a free Guide too, so every vertex of a patterned polygon drags alike (pin a Guide to keep it put). Holding Guides during drags made a copy's drag chase a center the tangency moved, and diverge. `tests/guides_test.rs` covers this behaviour. Nothing is skipped silently. `conflicting`/`redundant` come from `ConstraintSolver::diagnose()` (constraint indices; the rule is the doc comment on `SketchSystem::diagnose`), run after the solve, per Component: dependent rows carrying residual in an unsolved Component are Conflicting; in a Solved Component a minimal latest-first set of dependent constraints is Redundant. `temporary: true` constraints go through `add_temporary_constraint` and are **soft goals**: per Component the real constraints hold exactly and the temporary ones are minimized (least squares) within them. `status`/`SolverResult` and its errors consider only the real constraints (a Component of temporaries only is always Converged); temporaries are excluded from diagnosis, `dof` and `fullyConstrained`. The pre-solver skips a Component only when its real constraints and its goals all hold. Circle/arc fields resolve their center from `c_id` (a `c_id` field also accepts an explicit `center_id`). Arc fields also resolve the arc's `start_id`/`end_id`. WASM exports: `acsSolveSketch`, `acsConstraintCatalog`, `acsSolveSketchPlaneGcs`, `acsPlaneGcsConstraintCatalog` (`src/bindings/sketch_solve.rs`).
- `fullyConstrained` (JSON output) lists entities with 0 DOF, computed per connected component via `ConstraintSolver::fully_constrained_entity_ids()` (rank/null-space of each Component's own Jacobian, in `SketchSystem::fully_constrained_entity_ids`). Points/circles/arcs are analyzed directly (fixed variables count as locked); a line is included when both endpoints are. Only populated on a converged solve, `[]` otherwise. The demo tints these entities green (`renderer/theme.ts` `strokeForEntity`).
- In integration tests, `build_var_registry` is private to `sketch_system.rs` — construct a `VarRegistry` directly and call `register_entity(id, EntityType::Point, &Point::new(...))`.
