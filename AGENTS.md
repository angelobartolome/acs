# AGENTS.md

ACS is a 2-D geometric constraint solver: a Rust crate (`src/`) with WASM bindings, plus a React demo app (`wasm-demo/`).

## Commands

- Build: `cargo build`
- Lint (CI-enforced): `cargo clippy --all-targets --all-features`
- Test all: `cargo test`
- Single test file: `cargo test --test horizontal_test` (one integration test file per constraint in `tests/`)
- Pre-solver benchmark (a test, not `cargo bench`): `cargo test presolver_bench -- --nocapture`
- WASM build: `wasm-pack build --target web --out-dir pkg`
- C ABI tests (incl. a C smoke test that builds `libacs.a` and compiles `tests/c/smoke_test.c` with `cc`): `cargo test --features c-abi`
- Release: push a tag `vX.Y.Z` matching `Cargo.toml`'s version; `.github/workflows/release.yml` runs parallel jobs (clippy + tests + `cargo publish --dry-run` on Linux; one macOS job per Apple platform running `scripts/release.sh <platform>`; the WASM package on Linux via `scripts/release.sh wasm`), then one job publishes a GitHub Release and publishes the crate to crates.io (`CARGO_REGISTRY_TOKEN` secret; a manual run only builds). The crate is `acs-solver` on crates.io (`acs` is taken) but the library is `acs` (`[lib] name`), so `use acs::…`, `libacs.a` and wasm-pack's `acs.js`/`acs_bg.wasm` keep their names; the npm package is `acs-solver`, and `scripts/release.sh` renames its tarball to `acs-<version>.tgz`. Cargo.toml's `include` keeps the crate to the library (no demo, tests, scripts or docs). Release artifacts (static library + npm package): `scripts/release.sh [piece...]` -> `dist/` (no argument: everything, the Apple targets in one cargo invocation and wasm-pack alongside in `target/wasm-release`) (macOS arm64, iOS arm64, iOS Simulator `acs-<version>-<platform>.tar.gz` + the npm tarball `acs-<version>.tgz`; the version is the crate's)
- Demo: `npm run dev` / `npm run build` / `npm run test` (vitest) in `wasm-demo/`

CI (`.github/workflows/rust.yml`) runs clippy -> build -> test -> wasm-pack build. Keep clippy clean.

## Architecture

- `src/constraints/` — one file per constraint implementing the `Constraint` trait from `constraints/base.rs` as a **kernel**: `vars()` names the variables it reads by role (`Var::X/Y/Radius/StartAngle/EndAngle`, `xy(id)`; a Var is a number the solver moves, never a sketch Parameter (`param`)), and `eval(x, r, j)` computes residuals and partials over those *local* values. A constraint may also declare **Guides** (`guides()`, default none): inputs `eval` reads after the `vars()` that the constraint copies across (mirror axis, array center/direction). `j` has a column per `reads(c)` (= vars then guides) with exact partials for all of them, and every solve, drags included, moves Guides like any variable. The trait's provided `residual`/`jacobian` (and `eval_into`) do the ID lookup and accumulate (`+=`) into the global Jacobian, so shared points (two lines meeting at a corner) are handled once, for every constraint. Never write global Jacobian columns in a constraint.
- `src/solver.rs` — `ConstraintSolver`, the public Rust API (string-ID based): holds geometry + constraints, delegates `solve` and `fully_constrained_entity_ids` to `SketchSystem`.
- `src/sketch_system.rs` — built once per solve/analysis: the variable vector, and per Component its constraints (the sketch's plus each arc's implicit rules) and *free* columns (fixed variables are never columns). Skips already-solved Components (the pre-solver), solves the rest one by one on Component-sized systems, writes back to geometry, and runs the degrees-of-freedom analysis and Conflicting/Redundant diagnosis on the same structure (both over non-temporary constraints only). Temporary constraints are soft goals, solved by `solve_with_goals` (method in its doc comment: Dog-Leg restores the real constraints, then a feasible trust-region SQP: steps in the null space of the real Jacobian from a model with the Lagrangian's Hessian (central differences of the analytical Jacobians, `ReducedModel`), each re-projected with Dog-Leg. The second-order model is what gets a drag past a *fold*, where a real constraint changes only quadratically in the direction the goal needs, e.g. a fixed-length edge that starts exactly horizontal; a first-order method stalls there with the goal unmet — `tests/sketch_json_test.rs` `a_drag_at_a_fold_reaches_the_cursor`).
- `src/dogleg_solver.rs` — Dog-Leg trust-region numeric core: `solve_dl(x, eval)` over a plain vector and an `eval(x) -> (residuals, Jacobian)` callback; knows nothing about sketches. Owns `TOLF` (1e-10).
- `src/component_graph.rs` — `find_components`: union-find over the entities each constraint reads (`reads()`: Guides included, so a copy is solved with whatever moves its Guide). Guides are Component columns like any variable (a free axis keeps its own degrees of freedom in `dof`, and its copies aren't `fullyConstrained`).
- `src/constraint_catalog.rs` — the constraint vocabulary, one table: `constraint_catalog/native.rs` (`specs()`: one type per relationship, role-named fields, several rows per type = variants, chosen by the kinds of the referenced entities and the `extension` and `internal` flags (`InternalFlag`, catalog `internal: false`/`true`: the outside/inside variants of tangency between circles and arcs and of `distance` point–circle, circle–circle, circle–arc and arc–arc); `a`/`b` of `distance`/`tangent`/`concentric`/`equal` in either order; unsupported combinations rejected naming the kinds; `parse` builds a constraint). A row (`ConstraintSpec`) is a JSON type, fields by kind (point/line/circle/arc/ellipse/elliptical_arc/scalar/value/axis), an `ExtensionFlag`, an `InternalFlag`, an optional `check` of the resolved fields (run by `parse` before building; e.g. a shared endpoint) and a builder to `ConstraintType`. A field name `name[i]` is element `i` of an array field (`field_path`/`field_value`; the catalog emits `{name, index, kind}`); native `midpoint`'s `entities` is the only one. Shared resolution: lines to endpoints, circles/arcs to centers, ellipses to center + focus (`EllipseRef`), `axis` to `EllipseAxis` (`"major"`/`"minor"`), Parameter ids to constants (`References::scalar`) and property references (`{entity, property}`) to `Operand`s (`References::operand`, `property_operand`). `catalog_json` serves `acsConstraintCatalog`.
- `src/sketch_solve.rs` — JSON sketch API: `solve_sketch_json(request)` parses primitives, builds constraints through the catalog, solves, builds the response.
- `src/bindings/` — wasm-bindgen wrappers: `acsSolveSketch` + `acsConstraintCatalog`.
- `src/c_abi.rs` — behind the `c-abi` feature: `P3DSketch_Solve(request, &response)` / `P3DSketch_Free` (the sketch solver C ABI, header `include/p3d_sketch_solver.h`) over `solve_sketch_json` (`Ok` -> 0, `Err` -> 1; null/non-UTF-8 request and panics -> `invalid` response; 0.1.7 dropped the `vocabulary` argument; the symbol name is unchanged, so an old caller still links and must be rebuilt). The crate also builds a `staticlib`; the release script renames it `libp3d_sketch_solver.a` in the layout a consumer's setup script extracts. WASM doesn't use the feature.
- `pkg/` — **generated** by wasm-pack and gitignored; `wasm-demo` depends on it via `"acs": "file:../pkg"`. Run `wasm-pack build --target web --out-dir pkg` before `npm install`/`npm run dev` in the demo, and re-run it after any Rust change for the demo to pick it up.

## Adding a constraint

Touch all of these (grep an existing constraint like `Concentric` as a template). Tests fail until steps 1–5 agree:
1. `src/constraints/<name>.rs` (`vars` + `eval`, plus `guides` for inputs a drag must never move through it (with exact partials like the rest); reuse `segment.rs` for anything measured against a Line) + re-export in `src/constraints/mod.rs`
2. `ConstraintType` enum + `create_constraint` match in `src/constraints/base.rs`
3. A row in the catalog: a native row (or a new variant of an existing native type) in `src/constraint_catalog/native.rs`. It drives the JSON APIs, the catalog export, `tests/catalog_rows_test.rs` (every row solves through every entry point) and the finite-difference test, which builds each internal `ConstraintType` once from the first row that reaches it. Also add the variant to `variant_name`/`ALL_VARIANTS` in `tests/jacobian_fd_test.rs` (the exhaustive match won't compile otherwise).
4. Demo: an entry per native row in `CONSTRAINT_DEFS` in `wasm-demo/src/core/constraints/registry.ts` (unique `key`, native `type`, `extension` / `internal` if the row has the flag); `registry.test.ts` checks the set field-for-field against `acsConstraintCatalog`.
5. `tests/<name>_test.rs`; shared-point cases in `shared_point_constraints()` if two arguments can be the same point
6. Docs: constraint tables in `README.md`, `USAGE.md`; residual/Jacobian math in `SPEC.md`

## Conventions

- Rust edition 2024. Jacobians are analytical (derived in `SPEC.md`), not numeric — new constraints must include exact partial derivatives. Verify them by adding the constraint to `tests/jacobian_fd_test.rs`. Wrong product-rule terms have shipped before, including in `SPEC.md` tables, so derive from the code or check numerically rather than copying the spec.
- Geometry entities are referenced by string IDs; constraints on lines/circles usually take the underlying point IDs, not the line ID (see `ConstraintType` variant comments).
- The JSON API contract (input/output shapes, constraint type strings) is documented in `USAGE.md`; keep it in sync with `sketch_solve.rs`. Docs have drifted from code before — trust the code.

## Solver / API facts (verified in code)

- Convergence and pre-solver skip both use L-inf residual < `1e-10` (`TOLF` in `dogleg_solver.rs`). Per-component stats: iterations summed, errors maxed.
- A Line is a **segment**, never infinite. `PointOnLine`, `DistancePointLine`, `TangentLineCircle` (tangency point on the segment), and `MidpointOfLineOnLine` all measure against the segment via shared helpers in `src/constraints/segment.rs`. Parallel/Perpendicular/Angle use only direction. Only the Extension variants (`PointOnExtension`, `DistancePointExtension`, `TangentExtensionCircle`, `MidpointOfLineOnExtension`; `extension: true`), `SignedDistancePointExtension` (`offset`) and `MirrorPointExtension` (`mirror`) measure against the infinite line, via `line_signed_distance`; they exist for sketches migrated from infinite-line solvers.
- An Arc references center, start and end Points (`c_id`, `start_id`, `end_id`, all required) and owns `radius`, `start_angle`, `end_angle` as Vars; it sweeps counter-clockwise from start to end (sweep `(end − start) mod 2π`, 0 = full turn). Its endpoints always lie on it: `SketchSystem` adds an implicit `ArcRulesConstraint` per arc (`implicit_arc_rules`, indices past the sketch's constraints), which joins the arc's Component, holds exactly under soft goals, and counts in `dof`, `fullyConstrained` and diagnosis (a contradiction with it reports the *other* constraints Conflicting; in the Redundant walk it's never dropped), but is never itself reported. So a free arc has 5 DOF. No JSON type builds `ArcRulesConstraint` (there is no `ConstraintType::ArcRules`); `tests/jacobian_fd_test.rs` checks its Jacobian directly. Like a Line is its segment, an Arc is its span: `PointOnArc` and `TangentLineArc` (`on`, `tangent` with an arc) keep the point/tangency point within the span via `span_overshoot` in `src/constraints/arc_span.rs`; `TangentLineArc` also keeps it on the segment, like `TangentLineCircle`.
- An Ellipse (`{c_id, focus1_id, radmin}`) references center and focus Points and owns `radmin` as `Var::MinorRadius`; major radius `√(radmin² + |f − c|²)`, so a free ellipse has 5 DOF. Its kernels (`point_on_ellipse.rs`, `tangent_line_ellipse.rs`, `ellipse_axis_point.rs`, `ellipse_diameter.rs`) compute residuals in forward mode over `constraints/ellipse.rs` (`D<N>`/`V2<N>`/`EllipseFrame`: exact partials by the chain rule, like GCS's `DeriVector2`); reuse it for new ellipse constraints. Native `on` (curve ellipse), `tangent` line–ellipse (tangency point on the segment, like line–circle; no Extension variant) and `ellipse_axis` (`ellipse`, `point`, `which`: one point at *either* end of the axis; or `ellipse`, `a`, `b`, `which`: `EllipseDiameter`, the pair symmetric about the center along the axis, ends unordered). `fullyConstrained` lists an ellipse when its `radmin`, center and focus are all locked.
- An EllipticalArc (`elliptical_arc`: `{c_id, focus1_id, radmin, start_id, end_id, start_angle, end_angle}`) is an Ellipse plus endpoints at *parametric* angles (`P(t) = c + a·cos t·u + b·sin t·n`, from the major axis, counter-clockwise; sweep as an Arc's). Its values are `[radmin, start_angle, end_angle]`, the indices of `Var::MinorRadius`/`StartAngle`/`EndAngle`, so Ellipse kernels (`ellipse_axis`) take it unchanged (`FieldKind::EllipticalArc` resolves an `EllipseRef` plus `elliptical_arc_ends`). `SketchSystem` adds an implicit `EllipticalArcRulesConstraint` per elliptical arc (like `ArcRulesConstraint`), so a free one has 7 DOF. Native `on` (span: `PointOnEllipticalArc`), `tangent` line–elliptical arc (`TangentLineEllipticalArc`, on the segment and the span; at a shared endpoint `TangentLineEllipticalArcAtPoint`, `Args::tangent_line_elliptical_arc`) and arc–elliptical arc (only at a shared endpoint, `TangentArcEllipticalArcAtPoint`; the row's `check` rejects others), `ellipse_axis`. `EllipseFrame::point_at`/`tangent_at`/`param_angle` and `span_overshoot_d` are the shared helpers (`constraints/ellipse.rs`); `fullyConstrained` lists it when its own vars, center, focus and endpoints are locked. No `distance` to an elliptical arc (no closed form). SPEC §24, `tests/elliptical_arc_test.rs`.
- `isReference: true` on any geometry primitive implies `fixed` (`sketch_solve::fixed`): Reference Geometry's own values (point coordinates, circle radius, arc radius and angles, ellipse `radmin`) never move. Like `fixed`, it doesn't reach referenced Points.
- `ConstraintSolver::add_constraint` rejects constraints whose entities are missing or the wrong kind (`'id' is not a point`); the JSON API rejects the request with `constraint <id>: <msg>` and `constraintId`.
- Line–arc tangency where a line endpoint *is* an arc endpoint (same id, e.g. a slot) is built as `TangentAtPoint` (line ⟂ radius at the shared point) by `Args::tangent_line_arc`: the distance form (`TangentLineArc`) is degenerate there (zero Jacobian row at tangency → spurious Redundant, `dof` too high). Likewise arc–arc tangency where the arcs share an endpoint is `TangentArcsAtPoint` (radii collinear there, `Args::tangent_arcs`) instead of `TangentArcs`. And a line–circle/line–arc `tangent` (segment or Extension) whose line endpoint a real `on` holds on the same curve is rewritten to `TangentAtPoint` at that endpoint by `constraint_catalog::tangent_at_held_endpoints`, a pass over all of a sketch's parsed constraints in `sketch_solve` (otherwise the endpoint drifts µm from the tangent point and diagnosis reports spurious Redundant; issue #14, `tests/tangent_held_endpoint_test.rs`). The JSON API only: `ConstraintSolver::add_constraint` takes constraints as given. Native `tangent` between circles/arcs takes `internal: true` (inside, `|r1 − r2|`; never inferred; rejected with a line). Any constraint whose residual can only touch zero from one side at the solution has the same problem; prefer a form that changes linearly.
- `SolverResult::Converged` means L-inf residual < `1e-10`; a stall in a local minimum (vanished gradient, collapsed trust region) is `MaxIterationsReached`.
- `tests/jacobian_fd_test.rs` checks every constraint's analytical Jacobian against finite differences, including shared-point variants. It differences every variable a constraint reads, Guides included, and requires columns of variables it doesn't read to be zero. Add new constraints to `all_constraints()` (and `shared_point_constraints()` if two arguments can be the same point). Prefer unsquared residuals when the target can be 0 (a squared residual has a zero Jacobian row at the solution, which breaks convergence and DOF analysis).
- One vocabulary (`solve_sketch_json`, `acsSolveSketch`, `P3DSketch_Solve`): types `coincident`, `horizontal`/`vertical`, `parallel`, `perpendicular`, `collinear`, `normal`, `angle`, `direction`, `distance`, `offset`, `on`, `midpoint` (`entities: [point|line, line]`; the 0.1.5 `{point, line}` form and `midpoint_on` were removed in 0.1.7), `tangent`, `concentric`, `equal`, `radius`, `diameter`, `length`, `difference`, `x`/`y`, `horizontal_distance`/`vertical_distance` (signed `b − a` along one axis, `{a, b}` points or a `line`'s `p2 − p1`; built as `Difference` over coordinates, no kernel of its own; ordered, not commutative), `mirror`, `rotation`, `translation`, `ellipse_axis`, table in `USAGE.md` (there is no `symmetric`; `angle` with an `arc` is its sweep, only `0 < value < 2π`, residual unwrapped near the target; `distance` also takes point–circle, line–circle, circle–circle as signed gaps and line–line, SPEC §23, and circle–arc/arc–arc as the curve–curve tangency kernel held a gap apart (nearest points on the spans); `internal: true` selects the inside variant of tangency between circles/arcs and of point–circle/circle–circle/circle–arc/arc–arc distance). Variant inference and rejections are tested in `tests/native_vocabulary_test.rs`; the contract and solver behaviour through JSON (envelope, diagnosis, drags at a fold, Parameters, arcs, Reference Geometry, mirrors/arrays, ellipses) in `tests/sketch_json_test.rs`.
- The JSON contract is the `P3DSketch_Solve` contract: request `{version: 1, primitives, maxIterations?}`; response `{version: 1, status: converged|failed, primitives (same order), conflicting, redundant, dof}` plus ACS extensions `fullyConstrained` and `stats`. It returns `Err` with `{version: 1, status: "invalid", error, constraintId?}` for anything it can't read (wrong version or `maxIterations`, duplicate id, unknown type, missing field, missing/wrong-kind entity); `constraintId` names the offending constraint when there is one. `param` primitives are Parameters: constants (`value`) echoed back unchanged. Any `scalar` field takes a number, a Parameter id or a numeric string (unknown id -> rejected); `value` fields (only `difference`/`equal`) also take a property reference (`{entity, property}`) with props point `x`/`y`, circle/arc `radius`, ellipse `radmin`, which become `Operand::X/Y/Radius/MinorRadius` vars the solver moves. `offset` (`SignedDistancePointExtension`) is an Extension constraint signed by `side` (<0 -> -1, else +1; +1 = left of p1->p2). Array/mirror types: `direction` (`PointPointAngle`, residual `atan2`, no θ+π root), `mirror` (`MirrorPointExtension`, mirrors across the axis Line's Extension), `rotation` (rotate `source` about `center` by `angle`), `translation` (move `source` by `distance·count` along unit `from->to`); `angle`/`distance`/`count` are scalars. The axis/center/direction points are Guides, ordinary unknowns in every solve: moving them (by a drag or other constraints) moves the copy; real constraints move a free Guide as they need (Horizontal on a side of a patterned polygon turns it about a center that moves with it; a mirror whose source and image are both fixed turns a free axis onto their perpendicular bisector); and dragging the source or a copy may move a free Guide too, so every vertex of a patterned polygon drags alike (pin a Guide to keep it put). Holding Guides during drags made a copy's drag chase a center the tangency moved, and diverge. `tests/guides_test.rs` covers this behaviour. Nothing is skipped silently. `conflicting`/`redundant` come from `ConstraintSolver::diagnose()` (constraint indices; the rule is the doc comment on `SketchSystem::diagnose`), run after the solve, per Component: dependent rows carrying residual in an unsolved Component are Conflicting; in a Solved Component a minimal latest-first set of dependent constraints is Redundant. `temporary: true` constraints go through `add_temporary_constraint` and are **soft goals**: per Component the real constraints hold exactly and the temporary ones are minimized (least squares) within them. `status`/`SolverResult` and its errors consider only the real constraints (a Component of temporaries only is always Converged); temporaries are excluded from diagnosis, `dof` and `fullyConstrained`. The pre-solver skips a Component only when its real constraints and its goals all hold. Circle/arc fields resolve their center from the circle's/arc's `c_id`. Arc fields also resolve the arc's `start_id`/`end_id`. Every primitive, `param`s included, needs an `id`. WASM exports: `acsSolveSketch`, `acsConstraintCatalog` (`src/bindings/sketch_solve.rs`).
- `fullyConstrained` (JSON output) lists entities with 0 DOF, computed per connected component via `ConstraintSolver::fully_constrained_entity_ids()` (rank/null-space of each Component's own Jacobian, in `SketchSystem::fully_constrained_entity_ids`). Points/circles/arcs are analyzed directly (fixed variables count as locked); a line is included when both endpoints are. Only populated on a converged solve, `[]` otherwise. The demo tints these entities green (`renderer/theme.ts` `strokeForEntity`).
- In integration tests, `build_var_registry` is private to `sketch_system.rs` — construct a `VarRegistry` directly and call `register_entity(id, EntityType::Point, &Point::new(...))`.
